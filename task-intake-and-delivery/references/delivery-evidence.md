# Delivery evidence

Use only when the requested outcome includes an external file or agent handoff. Delivery authority is separate from preparing an artifact. Preserve private access and the approved destination; do not make a public link to solve a transport limitation.

Inspect the outgoing file, recipient, subject, body, and attachment representation before sending. Confirm supported file size and transport capability before a large transfer. Write for the medium and the assistant's established voice. A local path or a queued media directive proves preparation or queueing, not transport acceptance. Inspect the actual transport result and warnings for omitted attachments; distinguish prepared, queued, transport-accepted, and user-confirmed states. After an ambiguous send, reconcile before retrying to avoid duplicates. When a recipient reports a missing file, repair the attachment delivery rather than repeating its local path.

For private cloud fallback, permission to write a folder does not establish storage quota or ownership. Use a small authorized preflight where needed and verify the uploaded object and access controls. Do not upload private content to a new provider or recipient without authority.

For another agent, identify the actual watched inbox, queue, or session. Connectivity, artifact placement, consumer receipt, acknowledgement, active work, and completion are distinct evidence states. A branch or comment in an unwatched location does not prove the agent received instructions. Report only the strongest observed state, with a reachable artifact or next requirement. Do not add a watcher or repeated status messages solely to fill an evidence gap.
