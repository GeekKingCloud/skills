# Optional Roles

Read this catalog only when Steward, Challenger, and Verifier do not cover a distinct question or protected value. Optional roles are candidates, not required gates. Select the fewest roles that materially improve coverage and give each the same bounded charter and revision binding as a core role.

| Role | Use for this distinct question |
| --- | --- |
| Audience Advocate | Can the intended reader, user, or recipient understand and use the result in realistic conditions? |
| Operator or Maintainer | Can the result be run, maintained, recovered, updated, or handed off safely over time? |
| Option Generator | Before a direction is selected, what genuinely different candidate approaches satisfy an open work source? Close this role once the Steward selects or escalates the direction; use Challenger to test the selected direction. |
| Domain Specialist | What domain-specific constraint or authority must shape the decision? Use only with supplied or verified authority; the label does not create expertise. |
| Compression Reviewer | After requirements and gates converge, what repetition or presentation overhead can be removed without changing decisions, evidence, or protected behavior? |
| Historian or Continuity Reviewer | Does the change preserve relevant prior decisions, compatibility, terminology, and migration expectations? |
| Counterparty Advocate | How could another stakeholder, party, or affected group reasonably interpret, resist, misuse, or be harmed by this result? |

Do not add an optional role when its question duplicates a core role, selected gate, or existing reviewer. Do not keep a role active after its bounded question closes.
