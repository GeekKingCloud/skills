Use this brief for a coherent scene, event group or UI family within an authorized localization. The core skill and current owner contract govern; this reference does not authorize translation, integration, image work, delivery or resumption on its own.

## Outcome and inputs

Produce faithful, natural, context-aware target text for the assigned scope, preserving voice, source intent and approved terminology. Read the canonical immutable input, relevant neighboring context, project canon and exclusions. Reuse accepted source/target/context-bound work; a non-empty draft is not automatically accepted. Resolve material ambiguity from source evidence, not invented meaning.

The brief should name the outcome, exact inputs, allowed outputs, exclusions and remaining budget. Choose a substantial coherent milestone inside the project-wide budget, including validation and review; do not restart the allowance per batch or require a parent handshake for every small slice. Stop for a material scope change, exhausted budget, safety boundary or owner pause.

## Output and invariants

Write only assigned artifacts in the established schema. Preserve source bytes, stable IDs, required ordering, metadata, structural emptiness, executable syntax and exact control/placeholder sequences on their owning records. Keep choices and coupled lookup/display fields consistent without changing mechanics. Review joined dialogue and boundary context so a fluent row does not hide omitted, duplicated or displaced meaning. Use contextual terminology, not global substring replacement.

Use the project's established mechanical validator for source binding, schema, completeness and protected syntax. Add only checks needed for demonstrated coverage gaps. Mechanical validity does not establish linguistic quality or visible fit; character limits alone do not prove rendering. Do not launch runtime checks or edit images outside the assignment's authority.

## Review, reuse and return

Arrange one independent source-bound quality pass over stable coherent shards or the candidate—not both by default. Reuse valid prior acceptance. After repairs, rerun affected checks and confirm changed units and consumers; retain unaffected evidence. Reconcile stale labels before commissioning new review. Report review coverage honestly and keep translated content, independent acceptance and runtime proof distinct.

Return the exact output paths, source/output identity bindings, actual validation result, coverage and unresolved limitations in a compact handoff. Hash final bytes after the last edit when hashes are used. Preserve unique outputs outside disposable worktrees before retirement; do not create parallel ledgers or another review campaign just to tidy receipts.

Follow the owner's quiet-update policy rather than sending routine batch callbacks. Load other topical material only for a concrete technical problem, subject to the core's budget and boundaries.
